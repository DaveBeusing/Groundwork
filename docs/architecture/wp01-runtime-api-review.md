## Lifecycle, input and timing

Proposed Core module surface is `IEngineModule : IAsyncDisposable` with `ValueTask InitializeAsync(EngineModuleContext context, CancellationToken cancellationToken)`, `ValueTask StartAsync(CancellationToken cancellationToken)` and `ValueTask StopAsync(CancellationToken cancellationToken)`. Context supplies explicit capabilities and the validated finite host policy. Composition validates the dependency DAG and required capabilities before initialization. Stop/dispose are serialized with startup, idempotent, and terminal. The host initializes/starts in dependency order and stops/disposes in reverse order. A failed start stops all modules that reached started state. Each acquisition during initialization or startup is either registered for cleanup or rolled back by the acquirer. Cleanup includes the failing module and preserves its primary error separately from cleanup faults. Incomplete cleanup surfaces as a typed `IncompleteCleanupException` and may retain resources under a custodian.

For the integrated host, construct the shared clock and safety authority first. Diagnostics reserves reporting capacity before producer startup. ECS prepares world capture and writer authority before Jobs starts accepting work. Windows prepares the UI wake and input source independently of ECS and Jobs. Simulation starts only once the selected input, pipeline and reporting capabilities are ready. The UI pump can acknowledge readiness without waiting for Simulation, and Jobs readiness does not wait for a tick. The host starts the clock-driven loop after successful startup. These are runtime readiness edges in the composition root. The engine assemblies still reference only Core.

A stop request latches terminal intent, records the absolute shutdown deadline, and signals the wake path independently of any in-progress initialize/start operation. The coordinator cancels startup cooperatively off the pump and rejects later startup transitions. Each operation is given only the remaining deadline, including waiting for any startup operation to quiesce. Never call cleanup concurrently on the same resources when startup has not acknowledged release. On deadline, retain resources that startup can still reach and report incomplete cleanup. The custodian also retains pending UI-affine cleanup and routes eligible release back to the owning UI thread. Late acquisitions remain owned by the tracked startup operation until rollback or custody acknowledgment. Duplicate shutdown calls observe the same terminal operation and cannot extend its deadline. A Win32 close or cancellation wake must work while idle, while startup is pending, and when normal messages saturate the per-iteration event budget.

The Windows module owns an explicit UI-thread entry point and wakes its blocking message wait for shutdown. Native resources and pump callbacks stay on that thread. Core owns immutable platform-neutral `InputEvent` and `InputSnapshot` shapes plus `IInputSource.Capture()` for a single simulation consumer. An event carries kind, device category, normalized control code, value, monotonic sequence and timestamp from the injected clock domain. Sequence orders events with equal timestamps. A snapshot owns the current keyboard/mouse held state, bounded ordered transitions and a loss indicator. Capture drains transitions at `AcquireInput`. On overflow the held state remains authoritative and consumers can resynchronize from it. Focus loss atomically clears held state even if the event buffer is full. Close cancellation and resize/minimize lifecycle state are separate from gameplay input. No native handles or Win32 message codes cross Core.

Proposed clock seam is the BCL `TimeProvider` timestamp and frequency API, injected through composition. Simulation owns the accumulator. Represent debt in scaled integer units. For clock frequency `F`, base rate `R` and `T = TimeSpan.TicksPerSecond`, each elapsed timestamp unit contributes `R * T` debt units, each fixed step consumes `F * T`, and the cap is `configuredBacklog.Ticks * R * F`. Widen operands before subtraction or multiplication and reject configurations that exceed the supported arithmetic range. Before servicing steps, add eligible elapsed time to retained debt and cap the sum once. Preserve the exact excess as dropped elapsed units. Service up to the configured limit, even when new elapsed time is zero. For every running iteration:

```text
debtBefore + elapsedScaled = debtAfter + stepsApplied * F * T + droppedScaled
```

Defaults are `R = 60`, gameplay every third base step starting at tick 3, five base steps per iteration, and a quarter-second cap. The phase deltas are exactly 1/60 and 1/20 second respectively at those defaults. Validate positive frequencies/rates, a whole base-step divisor for the secondary cadence and a cap large enough for one step. Report exact debt before/after, dropped elapsed time, applied steps and overload episodes separately from observer interpolation. An episode begins when an iteration discards elapsed time after a running iteration that did not discard any, or when the first running iteration discards time. Compute interpolation from the fractional remainder, with output strictly below one. Pause freezes debt and publication. Resampling on resume excludes paused elapsed time. A backward timestamp or exhausted counter faults explicitly. A phase failure or cancellation that interrupts a tick routes through the fault/barrier contract. Recovery must account for any committed barrier before authorizing more execution and cannot silently replay mutations.

Use `Int128` for scaled values and per-iteration reporting. Check the configured cap and headroom for the maximum timestamp difference before accepting the configuration. Use checked counters for simulation identity, saturating counters with an explicit saturation indicator for cumulative metrics, and clamp binary64 interpolation to `Math.BitDecrement(1.0)` when conversion would round it up. The first start sample establishes an origin with zero elapsed time. A new pause takes effect at the tick owner's next iteration boundary after the active iteration settles. At that boundary sample, admit, cap and account for the final running interval without servicing steps. Repeated pause calls do not resample. Resume takes a new origin, retaining accrued debt and resetting the overload episode boundary. Repeated resume requests do not resample.

The scheduler owns the sequence `AcquireInput`, `BeginTick`, eligible gameplay, base tick, `CommitResults`, `PublishState`. The tick phase context carries tick identity, fixed rational step and immutable input. Both system phases read the state established at `BeginTick`. Simulation advances the tick once for each completed fixed step. No system callback can recursively enter scheduling, alter a sealed candidate set or publish observer state during a barrier. Validate boundary counts, jitter, fractional and zero-sample service, preexisting debt plus overload, pause/resume and failure before publication.

The following signatures are proposed interface declarations for review. `SimulationIteration` and the loop implementation stay in the Simulation assembly. The host can wait until `NextWakeTimestamp` or a platform wake signal and may call another bounded iteration immediately while debt remains. Only one iteration can be active. Run asynchronous coordination off the Windows pump thread or yield the pump between bounded iterations.

```csharp
// Groundwork.Core
public readonly record struct FixedStep(int Numerator, int Denominator);
public readonly record struct TickContext(ulong Tick, FixedStep BaseStep, InputSnapshot Input);
public readonly record struct BarrierOutcome(BarrierStatus Status, BarrierStamp? Stamp);

public interface ITickPipeline
{
    ValueTask<BarrierOutcome> BeginTickAsync(TickContext tick, CancellationToken cancellationToken);
    ValueTask RunGameplayAsync(TickContext tick, FixedStep gameplayStep, CancellationToken cancellationToken);
    ValueTask RunBaseAsync(TickContext tick, CancellationToken cancellationToken);
    ValueTask<BarrierOutcome> CommitResultsAsync(TickContext tick, CancellationToken cancellationToken);
    ObserverPublication TryPublishState(TickContext tick);
}

// Groundwork.Simulation public operation
ValueTask<SimulationIteration> AdvanceAsync(CancellationToken cancellationToken);
void RequestPause();
void RequestResume();
```

`SimulationIteration` reports the completed tick, steps applied, exact remaining and dropped scaled time, interpolation, scheduler state and nullable `NextWakeTimestamp`. A paused or terminal iteration has no time-based wake. Requests wake the coordinator and take effect only at its defined boundary. An iteration can report cancellation only after its currently owned publication is settled or fenced. Host shutdown is a separate terminal request.

`BarrierOutcome` reports `Committed`, `Unchanged` or `Stopped`, with a verified `BarrierStamp` for coherent terminal outcomes. Expected batch rejections are separate writer receipts. A barrier may complete despite wait cancellation if publication already occurred. The scheduler must learn that disposition before it can resume. Only the coordinator uses this pipeline. System callbacks receive immutable views and private command outputs. `TryPublishState` returns `Published`, `Blocked` or `PreparationFailed`. It performs the observer snapshot swap only after preparation succeeds and the same safety authority grants publication at the final transition. Observer notification is outside the operation, so a listener exception cannot undo the snapshot or turn publication into a retry.

Debit one step and advance the completed-tick counter at successful observer publication, with no cancellation point between that swap and the scheduler's accounting. Cooperative pause and ordinary shutdown take effect between ticks. If a fault or cancellation interrupts an active tick, retain the tick identity and last completed boundary and fence later ticks. A failure before any named barrier completed may be retried only under an explicitly reviewed recovery policy. If a named barrier already completed, a retry from the beginning would risk duplicate effects. The first implementation terminates on an interrupted partially committed tick. It retains the last published observer snapshot and reports the actual writer revision separately. Supervisor-directed continuation and pause remain available at coherent barrier boundaries with no unresolved interrupted phase.

## ECS and job handoff

Core candidates are the opaque identity and version values, immutable access declarations, ordering keys and receipt protocol shared by ECS and Jobs. ECS owns the world, storage, lease admission, snapshot creation and transactional writer. Jobs owns worker execution, dependency admission and result ownership. Composition supplies writer-only capability ports to the coordinator without a reference between the two assemblies.

- `WorldId` is a nonzero process-scoped `ulong` allocated monotonically with checked exhaustion. `EntityId` combines `WorldId`, `uint Slot` and nonzero `uint Generation`. Generation starts at one and an exhausted slot is retired permanently. The world distinguishes stale identity from a missing component. `BarrierStamp` binds the world, barrier, tick, epoch and committed revision. A target version combines presence with an opaque mutation stamp that cannot alias after remove/re-add. Checked exhaustion fails explicitly before publication.
- `ResourceKey` combines the world, registered component or reserved structural domain, and a discriminated world/partition/entity scope. Entity scope uses the full generational ID. Partition scope resolves using an immutable epoch-bound membership map. Canonicalize and deduplicate declarations before dispatch. Reject malformed scopes and conservatively reject or exclude uncertain overlaps. Different batches with overlapping same-barrier command targets all fail, even with an execution dependency. Entity destruction covers every component on that entity. Borrowed reads must drain before mutation.
- `SourceKey` contains world, tick, phase, system, partition and source ordinal. Only the tick owner assigns ordinals from canonical enumeration. Use `BatchId(SourceKey, BatchSequence)` and an increasing command sequence. Reject duplicate order keys before applying any candidate. `JobId` is an opaque lookup handle. The admission guarantee is stable ordering for equal eligible batch sets.
- Borrowed `ReadLease<T>` is a sealed, disposable capability bound to world, epoch and read scope. Access checks liveness and copies out data without handing out an untracked escaping `ref` or `Span`. An in-flight read retains its lease protection until the copy completes, including when disposal races it. Propose reference-free value components for the first copy-out and snapshot API, pending review of component eligibility. Ordinary barriers close admission and wait only for live-resource leases within the configured barrier deadline. Advance the epoch even for a no-op barrier after quiescence. Snapshot-only jobs own an immutable bounded subset with target versions and may span barriers. Snapshot epoch is provenance. The writer revalidates version, authority, dependency and eligibility when the result eventually reaches a commit barrier.
- Seal an immutable candidate set before validation and stage eligible nonconflicting batches against the same coherent barrier-entry state. `CommitResults` publishes pure component batches and queues entire structural or mixed batches for the next `BeginTick`. Revalidate deferred batches and commit them whole. Batch-local provisional IDs resolve only inside the committing batch. A staged failure leaves published state unchanged. Unknown partial publication latches terminal `StopWorld`. Invoke diagnostics and receipt observers after reaching a terminal transaction state, outside the writer gate. Reentrant mutation or publication attempts fail without modifying the current set.
- Job execution and writer publication have separate outcomes. Seal the emitted batch-ID set on successful execution. An execution dependency targets a declared commandless job. A commit dependency requires a trusted success receipt for every member of a nonempty sealed set. A zero-batch outcome is `CommitNotApplicable` and fails a commit prerequisite. Repeated receipts are idempotent, and a single rejected receipt invalidates the aggregate and all unpublished dependents. Already committed batches retain their receipts and effects. Recheck prerequisite authority at dispatch and publication.
- Coordinate admission, cancellation, terminal shutdown and writer publication through serialized authority. Cancellation that wins before publication prevents it. Completed commits retain their effects. Reserve bounded DAG nodes/edges, queue slots, deferred batches, receipt retention, snapshot/result bytes and emergency state before admitting work. A waiting dependency holds neither a worker slot nor a live lease. Release records when dependents and owners have acknowledged them and release memory only after producer quiescence. Reject over-capacity admission observably.

### Scope, capture and version enforcement

Core defines the shared values below. `ResourceScope` is a discriminated value with `World`, `Partition(PartitionId, PartitionRevision)` and `Entity(EntityId)` cases. Each world freezes its component type registry before admitting work. Structural wildcard includes all components. World scope covers the entire matching domain. Partition overlap uses frozen membership sets. A matching entity lies within a partition only when the admitted membership proves it. A job holds the intersection of admitted and currently authorized targets. Revalidate actual targets on every query, copy, snapshot and command. A partition identifier cannot expand an existing job's grant when membership changes. Recompute candidate conflicts at the current barrier before committing deferred work. Overlapping reads may execute together. An active read/write or write/write overlap excludes another ready job until the competing execution ends or its declared dependency is met. Execution order does not grant same-barrier write priority.

```csharp
public readonly record struct WorldId(ulong Value);
public readonly record struct EntityId(WorldId World, uint Slot, uint Generation);
public readonly record struct BarrierStamp(WorldId World, ulong Tick, BarrierKind Kind, ulong Epoch, ulong Revision);
public readonly record struct ResourceKey(WorldId World, ComponentTypeId Component, ResourceScope Scope);
public readonly record struct SourceKey(WorldId World, ulong Tick, TickPhase Phase, uint System, uint Partition, ulong Ordinal);
public readonly record struct BatchId(SourceKey Source, uint Sequence);
public readonly record struct JobDependency(JobId Prerequisite, DependencyKind Kind);

public interface IJobInput : IDisposable
{
    BarrierStamp CapturedAt { get; }
    ComponentRead<T> Read<T>(EntityId entity) where T : unmanaged;
}

public interface IJobInputSource
{
    JobInputCapture TryCapture(in JobInputRequest request);
}

public interface IJobCommandWriter
{
    BatchAppendResult TryAppend(in JobCommand command);
}

// Issued to the logical writer. The handle is an immutable view of one sealed candidate set.
public interface IJobPublicationSource
{
    CandidateSet SealCandidates(BarrierStamp barrier);
}

// Issued to the barrier coordinator. Workers and result observers cannot obtain it.
public interface IBarrierPublicationAuthority
{
    BarrierOutcome TryFinalize(PreparedBarrierPublication publication);

```

Default or foreign entity IDs and IDs from a disposed world are invalid. A destroyed or recycled slot's previous generation is stale. Missing component is a distinct result for a valid live entity. Creation reports exhaustion if no slot can safely be issued. ECS returns the captured value or absence together with its issued `TargetVersion` for the full entity ID and registered component. Versions advance only on a successful target mutation. Absence after a removal has a fresh stamp, and a worker cannot replace the captured token with a current token acquired independently. This prevents an absent → present → absent sequence or a token for a different entity from passing revalidation. Capture values and stamps from one coherent state. Check version exhaustion while preparing publication.

`ComponentRead<T>` distinguishes `Present`, `Missing`, `InvalidId`, `ForeignWorld`, `DisposedWorld`, `Stale`, `ExpiredLease` and `UndeclaredAccess`. Only `Present` and `Missing` carry the source-bound `TargetVersion`. Component registration for copy-out rejects pointers, handles and other payloads that can alias live mutable storage even if the type is `unmanaged`. `JobInputRequest` carries the trusted admitted source/grant, dependency authorization and selected input kind. Capture succeeds with a disposable capability or fails with a typed rejection such as expired grant, unmet dependency, busy barrier or exhausted budget. The scheduler owns the capability through completion and releases it only after producer quiescence. Appending commands transfers a validated bounded copy to the scheduler-owned buffer. Typed rejections leave ownership with the caller. Successful completion seals the entire buffer and transfers its reservation to the publication coordinator. The scheduler rejects appends after seal or cancellation. Workers never receive the writer receipt or publication capability.

`JobSubmission` freezes a `SourceKey`, `ImmutableArray<JobDependency>`, immutable read and command target declarations, result budget, and `JobInputKind` (`None`, `Borrowed`, `OwnedSnapshot`). Result producers receive a capability-limited execution context only after dispatch authorization. ECS owns state-bearing capture and creates the authorized lease or owned snapshot from committed state. At the next eligible system phase after all commit prerequisites have receipts, the Jobs module requests capture from the committed state for that phase. The original source key remains the stable admission identity. The input capability separately identifies the dispatch barrier stamp. Reject pre-captured state-bearing input for a commit-dependent job. For a job depending on A's deferred write to X, capture X only after A's actual commit, even when the dependent writes a different target. Never trust a caller-supplied job closure as proof that a declared ECS access was authorized. Creation requires an explicit structural grant. Its provisional ID is valid only in the emitting batch, and the writer verifies the requested destination against that grant.

### Publication authority and terminal outcomes

Jobs exposes a synchronous `TrySubmit(JobSubmission)` admission result with either a retained job handle or a typed rejection, plus a separate observation operation for execution and commit outcomes. The authoritative execution states are waiting for prerequisites, ready, running, succeeded, cancelled, faulted, and dependency failed. A running cancellation request records intent before asking the worker to stop. It never releases a worker's memory or lease before the worker acknowledges release. A successful completion transfers a sealed result envelope to the scheduler, which validates capacity, ownership and authorization before forwarding it. Writer receipts carry `BatchId`, a trusted `BarrierStamp` and `Committed` or `Rejected` with a reason. Authority comes from the writer-issued channel, independently of the receipt's field values. The coordinator projects job commit state from its sealed batch set and the authoritative receipts. A commandless execution dependency releases only after its output was sealed and validated as commandless. An executed job with multiple batches remains commit-pending until all commit, or becomes commit-failed on any rejection or cancellation of an unpublished batch. A successful receipt already recorded remains final. Duplicate matching receipts are idempotent. Foreign, conflicting or unexpected receipts fail validation and cannot satisfy a prerequisite.

Admission and retention are scoped to one world. Require prerequisite handles to be active and already admitted. Rejection of self, forward, foreign or expired references prevents a cycle before dispatch. Ready work is selected from the admitted ready set in stable source order. Atomically reserve capacity for each immutable descriptor and declaration list, dependency edge, retained output, receipt and terminal record before taking ownership. Caps cover both count and bytes. Owner handles and accepted dependents hold separately accounted retention references. Release these on owner disposal or dependent settlement. Abandoned handles consume a finite slot and further admissions reject when the configured bound is reached. Late lookup returns expired after reclamation. Custodian-held reservations still count against the process budget across runtime restarts.

The logical coordinator holds a non-reentrancy guard for an entire barrier, including finalization. `BeginTick` and `CommitResults` both close borrowed admission, prove quiescence and advance epoch. Reader admission, in-flight copy and release have a single accounting authority. A live-borrow deadline breach terminally stops and quarantines the world, leaves the current epoch, published state and pending queue unchanged, and never reopens publication. Preserve reachable resources until release is proved.

Preflight seals one candidate set, reserves all queue and receipt capacity, and stages ECS changes, revision, epoch, deferred queue consumption/admission and authoritative receipt updates before the commit point. The writer atomically publishes those effects together. The final serialized commit point rechecks dependency authority, cancellation, terminal stop and required safety state, with no callbacks or unbounded waits under that gate. A failed recheck aborts the staged world change, preserves the old committed world and records rejection through the writer. After a successful swap the same candidate cannot be applied again even if delivery of an observer notification fails. Deliver notifications after the logical barrier exits. Reentrant attempts while the barrier is active fail without entering mutation, even after the internal storage lock is released.

`CandidateSet` captures its trusted barrier identity, the fully validated ownership transfers available for preflight, and any previously deferred batches due at `BeginTick`. Sealing holds the batch reservations through terminal settlement and leaves later arrivals for a subsequent barrier. `PreparedBarrierPublication` is an opaque writer-issued value bound to that candidate set and its entry revision. It owns the proposed next world root, deferred queue delta, and receipt ledger delta plus the expected safety and cancellation generations. A successful finalization transfers that state to the authority. On rejection, release staging only after its owners quiesce. Only the coordinator can consume the preparation. The commit point changes one authoritative view of world state and bookkeeping, and all later job dispatch and receipt reads observe that view. A receipt callback is notification only.

## Fault supervision and cleanup

`FaultReport` carries classification, severity, subsystem, optional world/tick/phase/job/target IDs, correlation and distinct primary and cleanup outcomes. Worker reports have no proof field. The runtime preserves the primary exception on its operational error path. The diagnostic path copies bounded summaries and does not retain arbitrary exception graphs.

```csharp
public interface IFaultReporter
{
    FaultReportStatus TryReport(in FaultObservation observation);
}

public interface IRuntimeSafetyState
{
    RuntimeSafetySnapshot Read();
}

public interface ISafeBarrierSupervisor
{
    ValueTask<SupervisorDecision> DecideAsync(BarrierReviewRequest request, CancellationToken cancellationToken);
}
```

`FaultObservation` is an observational value with bounded numeric IDs/codes and optional bounded text. The report returns `Recorded`, `Coalesced` or `EvidenceLost`. `RuntimeSafetySnapshot` exposes the monotonic stop and loss flags, pending-fault generation and saturating counters. Observe them coherently as one control-state version. Bounded producer contention can lose an optional summary. It must latch required evidence loss without a sink call or unbounded retry when the required observation cannot be recorded. Separate immutable diagnostic detail from control state so that a reader cannot miss the loss flag while trying to read a busy summary slot.

Composition creates a per-world issuer/verifier capability pair. Only the world writer holds issuance authority. `WorldCoherenceProof` is opaque and immutable. It binds the issuing authority, current barrier stamp, verified dependency isolation and the exact pending-fault generation covered by verification. Issue it only after verifying actual committed state and verifying that the generation did not change during the check. The supervisor checks the issuer, stamp and covered generation. A decision carries `ContinueAtSafeBarrier`, `PauseForRecovery` or `StopWorld`, its proof stamp, a single-use request identity and the monotonic pending-fault generation. Consume the response at the serialized publication boundary only after rechecking those values and the safety latch. A new fault at the same revision invalidates a pending continuation. Duplicate, delayed or fabricated responses cannot authorize publication.

`BarrierReviewRequest` carries the opaque writer-issued proof, current fault generation and a unique request identity. Give its producer capability only to the barrier coordinator. A returned decision is authoritative only through the configured supervisor channel and expires with its request, deadline, generation or proof. Detect generation exhaustion and latch stop. Register safety-critical faults and evidence loss, terminal close and final authorization of each writer or observer publication on one linearizable control transition. A fault accepted before that transition invalidates the prepared authorization even if the actual world revision has stayed the same. A fault accepted afterward governs the next publication. Observers never use an unchecked diagnostic snapshot to authorize a commit.

Cancellation, dependency failure, stale result and write conflict can continue only after conclusive isolation and current proof. Invalid access and recoverable job faults default to pause with independently established coherence. Unknown critical faults stop absent reviewed safe-pause policy and proof. Unsafe partial commit is terminal. Lost required evidence, unverified proof, supervisor timeout or incomplete lease drain fails closed. Pause fences all new publication. It can leave the world available for inspection when coherence is known. Resume from pause requires a fresh authorized decision and all required evidence. Required evidence loss cannot be cleared by an ordinary resume. A terminal stop cannot be cleared by a later response.

Use separate producer and host-observer ports. Runtime admission supplies validated finite limits for normal event count and bytes, reserved emergency slots and bytes, per-event and per-field size, and total outstanding work. Reject admissions that exceed either the local or global reservation. Emergency state records bounded first-primary, cleanup and sink outcomes separately and exposes monotonic loss and stop flags with saturating counters. The host reads safety state independently of sinks. A failing sink is disabled and recorded directly in emergency state. No sink is called synchronously from a hot-path report or recursively from a sink-fault handler.

Require an explicit positive quota configuration at composition. Compute reservation sizes with checked arithmetic and validate local quotas against the process totals before admission. Include queue record overhead, copied target identifiers and redacted text storage, terminal bookkeeping, and retained custodian reservations. Charge a record until its last owner releases it, including queued or in-flight records held by disabled sinks. A report must fit both count and byte caps. Pre-reserve bounded primary, cleanup and sink summaries plus the safety control state for each admitted runtime or world. The emergency path is available even when ordinary capacity is exhausted. Delivery loss for optional timing, logging or summary details increments a distinct counter and does not assert lost safety evidence. Current fault classification, target/authority identities necessary to prove isolation, incomplete-cleanup state and terminal intent are required safety evidence. Missing required data latches safety evidence loss and prevents further publication until the supervisor applies the reviewed fail-closed policy.

Use one absolute shutdown deadline across modules. Terminal close and publication compete on the same authority, with the winning transition defining whether the publication may occur. Establish shutdown intent and its deadline without waiting for a producer or a gate that can invoke callbacks. Close admission and publication before cancellation and drain all owned producers, including snapshot and emergency producers. Dispatch cancellation callbacks and joins outside gates and off the simulation and UI hot paths. They share the same deadline and custody policy as other owned work. On deadline, transfer still-reachable buffers and reservations to a process-owned custodian. Return an explicit incomplete-cleanup fault, keep the world terminal, and reclaim only after proven release. Repeated cleanup cannot double-free or allow late publication. Separate the deadline and barrier budgets from a caller's wait cancellation. Validate their concrete configuration and bound composition during this review.

## Freeze checklist

- L2 confirms exact debt/episode sampling, phase deltas, timing origin and partial tick outcomes. L1/L2 confirm startup rollback and UI affinity with one shutdown deadline.
- L3A confirms ID/version exhaustion, borrow enforcement, quiescence and non-reentrant publication. L3B confirms zero/multi-batch receipt rules, bounded retention and the cancellation/publication linearization point.
- L5 confirms issuer/response authority, same-revision fault freshness, limit validation and fault handling under saturation, reentrancy and shutdown.
- The integrator freezes the exact signatures, budget configuration and test wiring, records the independent reviews, and submits the reviewed revision for owner acceptance under ADR-0007. Dependent code starts against the integrated contract.
