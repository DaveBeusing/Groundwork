# WP12-A01 · Planet generator V2

The [WP12 contract](wp12-underground-geology-contract.md) defines the downstream gates. This package provides a baseline brick source. WP12-B01 owns underground streaming, sweep/mesh/presentation validation and atomic depletion. WP12-C01 owns checkpoint dispatch and recovery. WP12-W01 owns the published content recipe and route, including spawn and traversal verification with the game capsule. WP11 Q02 and production acceptance remain open.

## Recipe and identity

`PlanetTerrainGenerator.Create` resolves the requested generator version using exactly its corresponding recipe. V1 still uses `PlanetDensityField` and PLF1 with the original digests and results. V2 uses `PlanetGeologyField`, generator version 2 and terrain schema 1. The generator validates the descriptor digest against the recipe. The descriptor still supplies world and planet identity, seed, lattice scale and material catalog identity.

The V2 SHA-256 input is 84 bytes. Bytes 0–3 are ASCII PGL2 and bytes 4–35 are the raw PLF1 digest. Bytes 36–75 are ten signed little-endian Int32 values in constructor order, from shallow band through shaft chance. Bytes 76–83 are the four little-endian UInt16 palette IDs in constructor order. Palette IDs are distinct and nonzero. Spatial lengths are in finest lattice cells. The recipe constructor is the validation authority for all ranges.

## Sampling

- Base density is computed by the unchanged V1 landform field using the embedded PLF1 recipe. The radius is converted to 1/256-cell units using the existing ties-to-even conversion. Strata classify uncarved depth after signed 3D value noise at the strata scale perturbs the band boundaries. Use ties-to-even division by 32768 to convert signed noise to the configured relief. Ore occupies only middle-host cells whose ore noise reaches the threshold and whose canonical lower vertex remains solid after carving. Material IDs carry no collision authority.
- The V2 seed streams are `5354524154410002` for strata, `4F52450000000002` for ore, `504F5254414C0002 + axis` for portals and `5348414654000002` for entrance ramps. Use the V1 SplitMix64 mixing and value-noise interpolation. Feature hashes mix the stream with the seed, then mix in signed X, Y and Z as their unsigned 64-bit bit patterns. Portal and entrance chances compare the upper 16 hash bits with the recipe threshold.
- Feature cells use Euclidean division by 64 with hub at local (32,32,32). A room uses radius 9. The lower cell owns each face portal. The two lateral offsets are the hash and the hash shifted by 16, each modulo 17 minus 8, applied to the hub's lateral coordinates. Each side uses a radius-5 normal stub to the same portal, 16 cells inward, then joins the hub by two lateral legs and one normal leg. The inner bends and room support stay clear of other faces. The shared stubs have the same clearance and field on the boundary. Before opening either half, sample base depth at the shared face point. Require a margin from both depth limits that covers the four-cell fade plus the worst base-depth variation in a four-cell box around that point. The bound adds radial displacement and per-layer trilinear noise variation with rounding. Both cells therefore agree on admission, and the depth fade stays inactive at the aperture.
- A designated entrance uses a radius-5 ramp. Its endpoint is 16 cells outward along the dominant radial axis of the cell centre (ties X, then Y, then Z), and 20 cells along the next axis, signed outward on each. A ramp opens the surface where it intersects the landform. Only the designated entrance feature can carve near the surface. Route selection must qualify real clearance and support, including the part of the route constrained by the depth envelope.
- Cavities use distance to a point or closed line segment. Axis-aligned segments clamp each coordinate. Ramps use a clamped rational projection, truncate the scaled squared distance, then use the same nearest integer square root as V1. The cavity field is radius minus distance in density units. Union takes the maximum. Each contribution adds a nonnegative share of the difference between cavity and base density, with a four-cell linear fade at support and depth limits and ties-to-even division. Rooms and portals are confined to the configured depth interval. Entrances can contribute from four cells above the base surface to the same deep limit. Outside support or that interval the contribution is exactly base density. Quantization is deterministic at zero, with WP11 zero remaining non-solid.
- Each density query considers one feature cell, one room, up to six portal paths of four segments each, and one ramp. The normal stubs are the only features whose support reaches a face. There is no neighbour search, cache, per-query heap allocation or persisted feature graph. The coordinate domain is the same as V1. The material query evaluates carving only for a candidate ore cell.

## Golden fixtures

`PlanetGeologyFieldTests` records the recipe digest and three canonical two-brick hashes, including signed keys and a 6,400,000 m radius. In canonical brick order, the digest appends little-endian signed Int64 density and, for owned cells, little-endian UInt16 material in Z/Y/X order with X innermost. The tests compare forward, reversed and parallel generation. They also exercise independently generated bricks around all three axes, sealed geometry, a designated ramp, depth and support clipping, both approaches closing when a depth limit would obstruct the portal, strata and ore. V1 goldens run through version dispatch with their existing expected values.
