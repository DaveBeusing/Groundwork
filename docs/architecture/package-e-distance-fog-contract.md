# Package E · Distance fog and day/night

Package E adds optional distance fog to the existing Groundwork D3D12 terrain pass. WYU owns the reference planet's clock, daylight, regional weather and save compatibility. The starting point is the [WP13 Windows handover](../wp13-handover.md), including the shared biome recipe, seeds 42 and 20261111, existing renderer handoffs and the exact Groundwork package baseline. [Groundwork #111](https://github.com/DaveBeusing/Groundwork/issues/111) · [WYU #41](https://github.com/DaveBeusing/wyu/issues/41)

This slice uses the existing terrain draws and the existing sky clear color. Atmospheric scattering, sky geometry, a rendered sun, dynamic shadows, precipitation, temperature and wind are separate packages. Ember Caves retains its existing palette, timing and save format.

## Groundwork renderer boundary

- Carry optional fog on the fixed-size value data for a scene and a paired volume camera. Use an additive property or overload that preserves existing constructor and deconstruction call sites. Rebuild consumers against the exact new package version. A clear-only frame has no fog. The portable frame and paired camera paths share the same validation.
- The proposed fog value contains linear blend-space RGB, StartDepthMeters, EndDepthMeters and MaxOpacity. Every component is finite. RGB and opacity are in [0, 1], start is nonnegative, and end is strictly greater than start. The depth span must be a normal positive float (at least 2^-126 m) so the inverse span remains finite on the shader path. The band need not be inside the clip range. An invalid explicit value is rejected even if its opacity is zero, using the existing invalid-frame or invalid-region result before changing sequence, pending frames or mesh registration.
- Use positive view-space depth, in metres along the camera forward axis. For the existing right-handed perspective projection this is the pre-divide clip W. Pass it as a perspective-correct vertex interpolant. Do not use screen-space depth, absolute planet coordinates or distance along a ray. The same camera and geometry must produce the same fog after a shared rebase within the readback tolerance.
- The shader applies the existing vertex color and tint, then blends RGB toward the fog color by MaxOpacity times saturate((depth - start) / (end - start)). Alpha stays on the original tint/vertex path. The clear color and depth buffer are unaffected. Absent fog and zero opacity use the original RGB path. Supply fog through the existing per-draw constants, with no second draw or new geometry. The paired camera for a new mesh and subsequent camera-only submissions use the same fog semantics.
- Time or weather changes only submit frame data. They do not advance terrain generations, reevaluate the biome color callback, invalidate publication, alter collision or trigger uploads. Preserve the neutral-mask, stop, GPU retirement and exclusive window/device/queue ownership rules from WP13.

## WYU fixed-step clock and daylight

- Use an unsigned 64-bit count of accepted 60 Hz environment simulation steps. Advance once per completed walking simulation step even with zero movement input, and once per accepted procedural flight step. Batch replay and render interpolation do not alter the count. Menu and suspension waits, loading, maintenance barriers, frame submission and recovery retries do not advance it. Use checked advancement and keep the last committed state recoverable on exhaustion. A flight abort leaves its saved preflight state intact.
- A day is 36,000 steps. Let p = (tick modulo 36,000) / 36,000. The sun direction in canonical planet axes is (0, sin(2πp), cos(2πp)), with +X as the rotation axis. Use the dot product against the normalized canonical camera position for solar elevation. This gives the +Y reference spawn a full day/night cycle. Smoothstep from −0.15 to +0.20 maps elevation to daylight in [0, 1]. Ambient RGB tint interpolates from 0.18 to 1.0 with alpha 1. Interpolate clear RGB between (0.025, 0.035, 0.075) and (0.18, 0.27, 0.41), with alpha 1. Use the same clock and canonical position for near terrain, the orbital scene and handoff masks.
- Interpolate the presentation state between accepted ticks without storing fractional time. At Continue the first frame uses the saved integer tick and restored pose. Preview settings and test toggles do not mutate the saved clock.

## Regional weather

- Use canonical planet-centred metres and a 256 m Cartesian grid. Region IDs are signed integer triples with centres at (i + 0.5) × 256 m. For each camera coordinate, floor(axis / 256 − 0.5) gives the lower neighbouring centre index. Trilinearly blend the eight surrounding targets using the fractional offsets. This rule handles negative coordinates and gives the same regional identity across a cube-chart change or render-origin rebase.
- Sample biome and base elevation at each region's representative point. Normalize the region centre onto the reference sphere, sample the base landform elevation there, then evaluate the WP13 biome weights at the resulting elevated point. Use the immutable world recipe so terrain edits, job order and camera-origin changes do not churn the region target.
- Each endpoint is keyed by seed, the three signed region indices, and a 60-tick segment index. Use stable unsigned 64-bit mixing, with each signed coordinate represented by its two's-complement bits. Freeze recipe ID, mixer, input order, constants and golden vectors in the WYU rule PR. The mixer supplies a normalized noise value u from its high 24 bits divided by 2^24. The target density is smoothstep(0.20, 0.85, 0.65u + 0.20 × meadowWeight / 255 + 0.15 × clamp((64 − elevationMetres) / 128, 0, 1)). The rule test vectors must include zero and nonzero density.
- Blend the current and next segment endpoints by the fractional in-game second, then blend the neighbouring regions. Refresh resident region targets at the one-second segment boundary. A newly required key is computed on admission, including a deterministic recomputation after eviction. Retain at most the current stencil of eight regions times two segments. Reuse entries common to consecutive stencils, retire keys outside the new stencil before admitting replacements, and compute misses deterministically. Cache contents and order have no effect on results.
- With interpolated density d, set start depth from 128 to 24 m and end depth from 768 to 128 m by linear interpolation in d. Use the day's clear RGB as fog RGB. Apply MaxOpacity = d × (1 − smoothstep(32 m, 72 m, altitude)), where altitude is camera radius minus reference radius. This gives a continuous fade before the existing flight renderer boundary and keeps the far orbit clear of local fog. Use the same mapping on descent. Daylight tint still applies in orbit. A disabled Package E frame uses the WP13 tint and clear defaults and omits fog.

## Save and Continue

Keep the Groundwork checkpoint schema, terrain revision and edit payload. Extend only the existing WYU reference-world game payload. Use magic WYUVOL03, followed by an unsigned little-endian tick at offset 8 and a flags byte at offset 16. Bit 0 indicates a landing record, and all other bits are reserved. Exact length is 17 bytes without a landing, or 53 with the existing 36-byte WYUVOL02 landing body at offset 17. Preserve its existing pose, revision and flight-tick checks.

Read WYUVOL01 and WYUVOL02 with tick 9,000, preserving any valid landing and leaving the original file intact until an explicit save. Validate exact length and flags before accepting WYUVOL03. Unknown versions retain the existing unsupported handling and malformed payloads retain the existing recovery handling. Commit the environment tick with the pose and world revision in the same checkpoint transaction. Weather is reconstructed from the restored seed, tick and canonical pose. No cache entries or interpolated colors enter the file. Existing interrupted-write recovery must recover a complete old or new snapshot.
