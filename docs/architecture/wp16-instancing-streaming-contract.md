# WP16 · GPU instancing and prop streaming contract

[Groundwork #114](https://github.com/DaveBeusing/Groundwork/issues/114) owns the renderer and bounded cell transport. [WYU #44](https://github.com/DaveBeusing/wyu/issues/44) owns the Far Horizon assets, biome rules, placement and distance policy. Start from WP11 publication and the Package B biome palette. E, G, WP12 and WP15 are optional integrations. WP15 sunlight and terrain shadows retain their opt-in status. Prop collision, moving objects, terrain-shadow casting and prop-shadow receiving are outside WP16.

## Cells, placement and publication

- WYU keys cells in a canonical planet lattice independent of render origin, camera, load order and mesh LOD. Version the cell partition and placement recipe. Order candidates deterministically and derive stable instance IDs from the world seed, recipe, cell key and candidate ordinal. A cell owns its boundary by a half-open partition. LOD changes preserve ID and transform.
- Place against a bounded read lease of the published terrain using its slope and elevation. Each candidate result carries the cell key, request generation, world and renderer epoch, source terrain revision and the coverage it sampled. Workers release leases on completion, cancellation or rejection. Missing coverage defers placement and issues zero brick requests. WYU derives placements again after Continue from the saved seed, recipe and terrain. It does not serialize renderer residency.
- The terrain publication path supplies a conservative invalidation set covering the edited region and all cells whose support samples could have changed. At the first submission that can present the new terrain revision, suppress affected old cells unless their matching replacement is ready. Carry forward unaffected cells only when coverage remains valid and the invalidation set proves their support was unchanged. If the invalidation set is unavailable, suppress the previous revision's cells. Delayed work may never make obsolete instances visible again.
- Apply cell residency changes at a frame boundary through the renderer owner. A ready candidate for a matching publication replaces its cell as a unit. Reject stale world, epoch, request or terrain results at staging and recheck at installation. Install terrain and its prop visibility cut coherently in the same recorded frame. Camera-only changes do not advance the terrain generation. Clear-only frames, resize and near/far handoff obey existing presentation ownership. The far renderer omits near props.

## Rendering and visibility

- Share one immutable geometry buffer per model and LOD across cells. Validate assets and instance input before admission, including finite canonical coordinates, valid rotation and positive scale, asset identity, packed color and checked byte sizes. Keep world placement in canonical double precision and encode bounded cell-relative positions in the upload.
- Use a 32-byte baseline instance record containing float3 cell-local translation, packed quaternion, uniform scale, RGBA8 tint and a frame-independent cell slot. Keep stable IDs in CPU metadata. Define exact encoding and error bounds in the portable API PR. Fetch instance transforms via the instance ID and apply a cell-to-render-origin translation computed in double precision before conversion to float. Camera turns and rebases reuse immutable mesh and instance bytes.
- Test conservative cell bounds against the camera frustum and render range. Bounds include all supported model LODs and instance scale and rotation. Select one LOD per instance using canonical distance and stable hysteresis. WYU starts rocks and trees within 128 m, grass within 32 m with deterministic thinning, and uses two mesh LODs with separate enter/exit distances for rocks, scree and trees. WYU fixes and documents the final thresholds before route qualification.
- Bucket visible instances by mesh, material and LOD in bounded reusable scratch. Encode visibility with frame-local references to resident instances. Submit one indexed instanced draw per nonempty group using a read-only instance buffer and a frame-local indirection table. Count writes of that lightweight metadata separately from mesh and instance payload uploads. Charge its CPU cost and all backing storage, including multiple in-flight frames, to WP16. Asset admission must bound the number of drawable groups to 96 for the qualified stress profile. Never truncate a qualifying visible group silently. Props depth-test and write against terrain and consume existing fog when enabled. Existing terrain lighting and sky passes retain their contracts.

## Admission, backpressure and GPU custody

- Use a disjoint prop quota for placement slots, pending cell bytes, upload slots, resident instances, geometry assets and retirement slots. Charge resources before admitting work. Coalesce repeated cell requests, prioritize nearest eligible cells with a canonical tie-break and discard stale or superseded speculative results. At quota exhaustion keep valid resident cells and defer newly wanted ones. Report per-reason counts and high-water marks. A cell exceeding the frame upload allowance requires bounded chunked staging with atomic install.
- Reserve independent capacity for terrain movement, edits and recovery. Prop work may consume its own budget when protected work is ready; it may never consume protected slots or block protected submission behind an unbounded copy. If a prop copy cannot be admitted, submit terrain with the valid resident prop subset. Under queue pressure, invalidation remains immediate even when regeneration waits.
- Cap total actual additional prop upload bytes at 2 MiB per frame, including meshes, instance payload and GPU-visible per-frame metadata. Account logical transfer and native allocations separately. Capacity includes staging, scratch, admitted candidates, resident resources and allocations retained after replacement. No prop mesh or instance-data transfer on camera-only turns with unchanged cells. Rebase may update coordinate metadata. Geometry stays alive through its last draw or transfer fence. Stop and device loss follow the existing queue-custody contract with release after retirement or confirmed removal. Resize cannot reuse in-flight metadata.

## Acceptance and implementation order

1. Review this contract. Implement the portable cell admission, deterministic visibility and LOD API with tests for stable IDs, bounds, ordering, hysteresis, stale results, coverage and saturation.
2. Implement D3D12 grouped drawing and staging. Require CI WARP color/depth readback of multiple transforms and correct tint from one shared indexed draw. Run WARP and NVIDIA with Debug Layer and DRED for before/after rebase alignment, view/LOD changes without mesh or instance transfers, delayed and failed staging, saturation, edit suppression in the first successful Present, resize, stop and device loss. Verify existing terrain edit and publication tests. Assert native counters for draw count, uploaded bytes and retained memory.
3. Archive verified immutable Groundwork master packages and pin the exact archive in WYU. Use both fixed Far Horizon seeds to verify unload/reload, Save/Continue, cell and LOD transitions and removal of an unsupported tree on the first visible edited frame. Qualify WYU from clean master checkouts and record workstation evidence separately from reference-class results.

Use Windows x64 Release at 1920 × 1080 on the WP11 reference class. Compare props off/on with the same Package B state active, matched E/G/WP15 settings, seed, route, adapter, driver and verified presentation mode. Record at least five independent pairs and 2,000 measured frames per variant per phase after warm-up. Report per-run and pooled p95/p99 for dense vegetation, quick turns and cell/LOD traversal. The separate stress fixture must simultaneously show at least 50,000 grass instances and 2,000 rocks, scree and trees after culling. Confirm visible counts and draws from native submissions.

| Metric | Gate |
| --- | --- |
| Prop GPU and draws | p95 at most 2.0 ms and p99 at most 3.0 ms per phase using GPU timestamps. At most 96 additional draws per stress frame. |
| Total GPU frame | At most +15% p95 and +20% p99 per phase. Both absolute and relative GPU gates apply. |
| Render CPU | p99 at most 0.50 ms for visibility, LOD and draw recording together. Zero prop-related heap allocations after warm-up. Report placement time and queue wait separately. |
| Peak memory | At most 64 MiB additional CPU and 64 MiB additional GPU, including staging, scratch, assets and retired resources. |
| Uploads and terrain | At most 2 MiB additional uploads per frame and zero new terrain brick requests. Verify movement and edit progress with saturated prop placement and upload capacity, then repeat under the WP11 reference pressure cases. |
